\Abstract{Inside a warehouse, managers decide where to place storage and pickup areas, how to route material flow, how many forklifts and workers to run and which picking and loading strategies to follow, usually by rules of thumb. Each new layout normally needs a new simulation model, which is slow and requires an expert. We want to build one generic, parameter driven discrete event model of a warehouse, covering receiving, putaway, storage, order picking, consolidation, staging and loading, that a non-expert can configure and run. On top of this framework we plan to develop an automatic model generation framework: the user draws a facility on a grid of standard building blocks and the complete simulation model is generated from it. The framework is used to size forklifts and workers, compare storage and pickup allotments and test operating strategies under synthetic stochastic demand.}

\section{System Selection \& Problem Statement}

\subsection*{The System}
The internal operations of a warehouse. Inbound pallets arrive at the docks, are checked in a receiving buffer and put away to storage by forklifts. Customer orders release picking tasks; picked items are consolidated, held in pickup areas and loaded at outbound docks. Trucks appear only as the arrival and departure points at the dock. The model is built in three components:
\begin{itemize}
  \item \textbf{User Interface:} a non-expert sets layout, docks, forklifts, volume and policies, launches experiments and reads a KPI dashboard.
  \item \textbf{Generic Modelling Framework:} reusable building blocks (Dock, Forklift/charging, Passage), generic process logic and generic agents for pallets, orders, forklifts and workers.
  \item \textbf{Data \& Model Assembly:} stores configurations and input distributions, assembles the runnable model and exports results.
\end{itemize}

\subsection*{Highlight: Automatic Model Generation}
\noindent{\color{color2}\vrule width 2pt}\hspace{0pt}\colorbox{color2!10}{\parbox{\dimexpr\columnwidth-2\fboxsep-2pt\relax}{\small Building a new AnyLogic model for every layout is the main cost of simulation-based layout planning. We want to generate it automatically. The user fills a grid matrix where each cell is a building block (D = dock block, F = forklift block, P = passage, 0 = empty). A generator reads the matrix and creates the space markup, walls, docks, storage and pickup areas and the forklift path network at runtime. Any facility shape (I, L, T, U, H) then becomes a one-click experiment instead of a modelling task. This is built as an extension on top of the working framework.}}

\subsection*{The Problem}
Inside the warehouse, poorly allotted storage and pickup areas, long or conflicting forklift paths and unbalanced forklift and worker capacity cause excess travel, congestion in aisles and buffers, and orders that miss their loading slot. We study:
\begin{enumerate}
  \item \textbf{Allotment \& material flow:} where should storage and pickup areas sit relative to the docks, and how should forklift paths be routed, to minimise travel distance and shipment cycle time?
  \item \textbf{Resources:} what is the minimum number of forklifts and workers that meets the service level at peak volume, and which resource is the bottleneck?
  \item \textbf{Strategies:} how much do storage assignment, picking and loading strategies improve performance at zero capital cost?
  \item \textbf{Usability:} can one generic model, and ultimately one generated from a drawing, answer these without manual rebuilding?
\end{enumerate}
